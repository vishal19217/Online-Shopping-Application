Flyway + Dockerized MySQL — Errors & Fixes

1. MySQL init.sql never ran → ERROR 1049 Unknown database
- Cause: docker-entrypoint-initdb.d/*.sql runs only when the data dir is empty. My bind-mounted docker/mysql/data/ was already populated from a prior run, so MySQL skipped all init scripts.
- Fix: docker compose down → move/delete the stale docker/mysql/data → docker compose up -d so it re-initializes.

2. docker-compose.yml bugs
- Cause: invalid version: '4' (Compose only goes to 3.x); corrupted volume target /var/lib/mysqlup -.
- Fix: removed version:; corrected volume to - ./docker/mysql/data:/var/lib/mysql.

3. Flyway didn't run — zero log lines, no flyway_schema_history
- Cause: Spring Boot 4 split autoconfig into per-feature modules. Raw flyway-core = library only; the FlywayAutoConfiguration (that triggers migrations on startup) lives in the separate spring-boot-flyway module, which I didn't have.
- Fix: replaced flyway-core with spring-boot-starter-flyway (keep flyway-mysql). Verify with mvnw dependency:tree | grep flyway → must show spring-boot-flyway.
- Diagnosis tip: log shows Hikari + Hibernate but no Migrating schema = autoconfig missing (wiring), not a migration error.

4. Separation of concerns
- init.sql → only CREATE DATABASE IF NOT EXISTS. Flyway V1/V2 → tables + seed data. Keep ddl-auto=none.

5. Entity ↔ schema name mismatch (runtime break, even with table created)
- Cause: Boot's default snake_case naming: @Table (no name) → table inventory not t_inventory; field skuCode → column sku_code not skucode.
- Fix: pin names — @Table(name = "t_inventory") and @Column(name = "skucode").

6. Stale incremental-compile errors
- Cause: spring-boot:run reported phantom syntax errors in already-valid files; real error was elsewhere (incomplete controller method).
- Fix: mvnw clean compile to get the true first error.

7. Verify migrations without the app compiling
- mvnw org.flywaydb:flyway-maven-plugin:<ver>:migrate -Dflyway.url=... -Dflyway.user=... -Dflyway.password=... -Dflyway.locations=filesystem:src/main/resources/db/migration
